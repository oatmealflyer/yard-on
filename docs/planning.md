# Yard ON — 프로젝트 개발 기획서

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | Yard ON (야드온) |
| 서비스 대상 | 컨테이너 야드를 이용하는 거래처 직원 |
| 프로젝트 목적 | 컨테이너 반입·반출 접수 및 작업 현황 조회 |
| 개발 목적 | React 클래스형 컴포넌트의 구조와 생명주기 학습 |
| 기술 스택 | React, JavaScript, React Router, CSS |
| 개발 환경 | Node.js 18.18, Create React App |
| 데이터 | Mock Data |
| 1차 개발 목표 | 4시간 |

### 서비스 기획 의도

거래처 직원이 당사 야드에 맡긴 컨테이너의 접수 내역과 작업 진행 상태를 편리하게 확인할 수 있는 웹 서비스를 구현한다.

사용자에게 필요한 정보를 우선 제공하고, 신규 접수 요청 기능을 추가하여 거래처와 야드 운영사 간 업무 편의성을 높이는 것을 목표로 한다.

## 2. 핵심 사용자 요구사항

1. 자신의 거래처에 해당하는 접수 내역만 확인할 수 있어야 한다.
2. 컨테이너별 입고일, 터미널 반입 가능일 및 작업 상태를 확인할 수 있어야 한다.
3. 개별 컨테이너의 Booking, 선사, 터미널, 차량 정보를 상세 조회할 수 있어야 한다.
4. 신규 반입·반출 접수를 요청할 수 있어야 한다.
5. 당일 접수는 제한하고 당사 전화번호를 안내해야 한다.

### 개발 범위 제외

- 수출·수입 구분
- 혼재 화물 관리
- 야드장치 및 기존 완료 칼럼
- 자동배차 및 반출 순번 변경
- 실제 데이터베이스 및 백엔드 API 연동
- 실제 직원 승인 시스템

## 3. 화면 구성

### 3.1 로그인 페이지 — LoginPage

**목적:** 거래처별 접수 내역 구분

- 아이디: 사업자등록번호 10자리
- 비밀번호: 숫자 4자리
- Mock Data 기반 로그인
- 로그인 성공 시 접수 내역 목록 페이지 이동

※ 실제 운영 환경에서는 별도의 보안 인증 체계가 필요하다.

### 3.2 접수 내역 목록 — OrderListPage

**목적:** 거래처의 컨테이너 접수 및 작업 현황 확인

**화면 구성**

- 상단 메뉴: 접수 내역 / 신규 접수
- 조회 탭: 전체 / 반출 / 반입
- 기본 화면: 전체 접수 내역
- 컨테이너 중심의 테이블 구성
- 개별 행 클릭 시 상세 페이지 이동

**테이블 표시 항목**

| 항목 | 설명 |
|---|---|
| 컨테이너번호 | 컨테이너 식별번호 |
| 입고일자 | 야드 입고일 |
| 터미널 반입 가능일 | 터미널 반입 가능 예정일 |
| 작업 구분 | 야드 반입 / 반출 |
| 작업 상태 | 반입 완료 / 보관 중 / 반출 예정 / 반출 완료 등 |

작업 상태는 아이콘과 텍스트를 함께 표시한다.

※ 작업 구분과 작업 상태는 서로 다른 데이터로 관리한다.

### 3.3 컨테이너 상세 현황 — OrderDetailPage

**목적:** 개별 컨테이너의 업무 정보 확인

**표시 항목**

- 업체명
- 접수번호
- 컨테이너번호
- 입고일자
- 입고차량번호
- 터미널 반입 가능일
- 접안일
- 반출차량번호
- 선사코드
- Booking 번호
- 씰 번호
- 컨테이너 타입
- 총중량(WT)
- POD 코드
- 모선·항차
- 반입터미널
- 작업 상태
- 반출 예정 순번(조회 데이터 확보 시)
- 메모 및 비고

※ 기사 연락처와 청구 정보는 1차 화면에서 제외한다.

※ 야드 보관 위치와 실제 터미널 도착 여부는 데이터 확보 후 추가한다.

### 3.4 신규 접수 — NewOrderPage

**목적:** 거래처의 신규 반입·반출 접수 요청

**1차 최소 입력 항목**

- 접수 유형: 반입 / 반출
- 컨테이너번호
- 희망 작업일

**접수 처리 절차**

1. 거래처가 접수 정보를 입력한다.
2. 희망 작업일이 당일인지 확인한다.
3. 당일이면 온라인 접수를 제한하고 당사 전화번호를 안내한다.
4. 접수 가능한 날짜이면 최종 확인창을 표시한다.
5. 사용자가 확인하면 모의 접수 요청을 생성한다.
6. 요청 접수 안내 후 목록 페이지로 이동한다.

**승인 정책**

- 실제 접수 요청은 당사 직원이 수동 승인한다.
- 승인 전 요청은 정식 접수 목록에 표시하지 않는다.
- 1차에서는 프론트엔드의 모의 요청 처리까지만 구현한다.

## 4. 사용자 동선

### 4.1 접수 내역 조회

로그인 → 전체 접수 내역 → 반입/반출 필터 선택 → 컨테이너 선택 → 상세 현황 확인 → 목록 복귀

### 4.2 신규 접수 요청

로그인 → 신규 접수 → 접수 정보 입력 → 날짜 검증 → 최종 확인 → 요청 처리 → 목록 복귀

당일 접수 요청은 정식 접수로 생성하지 않는다.

## 5. 데이터 설계

기존 실무 접수 양식을 참고하여 Mock Data를 구성한다.

### 5.1 접수 데이터

| 필드명 | 설명 |
|---|---|
| orderId | 접수번호 |
| companyId | 사업자등록번호 |
| companyName | 업체명 |
| containerNo | 컨테이너번호 |
| operationType | 반입 / 반출 |
| inDate | 입고일자 |
| inVehicleNo | 입고차량번호 |
| terminalAvailableDate | 터미널 반입 가능일 |
| arrivalDate | 접안일 |
| outVehicleNo | 반출차량번호 |
| shippingLine | 선사코드 |
| bookingNo | Booking 번호 |
| sealNo | 씰 번호 |
| containerType | 컨테이너 타입 |
| weight | 총중량 |
| podCode | POD 코드 |
| vesselVoyage | 모선·항차 |
| terminal | 반입터미널 |
| yardStatus | 작업 상태 |
| exportSortNum | 반출 예정 순번 |
| memo | 메모 |
| remarks | 비고 |

### 5.2 데이터 설계 원칙

- 사업자등록번호를 기준으로 거래처 데이터를 구분한다.
- 접수번호를 고유 식별자로 사용한다.
- 목록은 컨테이너 중심으로 표시한다.
- 반입·반출 구분과 작업 상태를 별도 필드로 관리한다.
- 실제 접수 양식에 없는 상태값과 순번은 학습용 Mock Data로 구성한다.
- 실제 데이터 연동 시 기존 백엔드의 반환 필드에 맞춰 조정한다.

## 6. React 컴포넌트 구조

```text

│
├── pages/
│   ├── LoginPage.js
│   ├── OrderListPage.js
│   ├── OrderDetailPage.js
│   └── NewOrderPage.js
│
├── components/
│   ├── Header.js
│   ├── OrderTable.js
│   ├── StatusBadge.js
│   └── ContainerInfo.js
│
├── data/
│   ├── mockOrders.js

    └── common.css
```

### 역할 구분

- **App.js:** 라우팅 및 전체 화면 구조
- **pages:** 각 페이지의 화면 구성 및 데이터 처리
- **components:** 재사용 가능한 UI 컴포넌트
- **data:** 테스트용 데이터
- **styles:** 공통 CSS

## 7. React 학습 목표

클래스형 컴포넌트를 중심으로 다음 개념을 학습한다.

| 개념 | 학습 내용 |
|---|---|
| Component | 역할별 컴포넌트 생성 및 호출 |
| Props | 부모에서 자식 컴포넌트로 데이터 전달 |
| State | 화면의 현재 상태 관리 |
| setState | 탭 및 화면 데이터 변경 |
| render | 컴포넌트 화면 렌더링 |
| componentDidMount | 마운트 시점 확인 |
| componentDidUpdate | Props 및 State 변경 확인 |
| componentWillUnmount | 언마운트 시점 확인 |
| Routing | 페이지 이동 및 상세 데이터 연결 |

## 9. 향후 확장 계획

### 9.1 실제 접수 및 승인 연동
- 거래처 접수 요청을 당사 시스템으로 전송
- 직원의 수동 승인 및 반려 처리
- 거래처별 요청 상태 조회

### 9.2 당일 접수 문의 알림
- 당일 반입·반출 요청 시 전화 문의 안내
- 확인 버튼 클릭 시 거래처와 요청 내용을 당사 시스템에 전달
- 정식 접수와 문의 이력을 구분하여 관리

### 9.3 컨테이너 사진 조회
- 반입·반출 시점별 컨테이너 사진 표시
- 촬영 일시 및 사진 구분 정보 제공

### 9.4 배차 및 반출 순번 연동
- 기존 배차 조회 프로시저를 활용한 데이터 연동
- 배차 차량번호 조회
- 변경 가능한 반출 예정 순번 표시

### 9.5 추가 사용자 편의 기능
- 컨테이너번호 및 Booking 번호 검색
- 접수 요청 이력 조회
- 보관 기간 및 실제 반출 시각 조회

## 10. 1차 개발 완료 기준

1. 테스트 거래처 계정으로 로그인할 수 있다.
2. 로그인한 거래처의 접수 내역만 표시된다.
3. 전체 / 반출 / 반입 탭을 전환할 수 있다.
4. 컨테이너를 선택하여 상세 정보를 확인할 수 있다.
5. 작업 상태, 배차 차량번호, 반출 예정 순번을 표시할 수 있다.
6. React 클래스형 컴포넌트의 생명주기를 확인할 수 있다.
7. 페이지별 컴포넌트와 공통 컴포넌트가 분리되어 있다.

신규 접수 기능은 추가 개발 목표로 설정하며, 4시간 내 핵심 조회 기능의 정상 작동을 최우선으로 한다.
